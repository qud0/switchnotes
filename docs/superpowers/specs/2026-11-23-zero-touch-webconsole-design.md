# Zero-Touch WebConsole: Внутрибраузерная USB/COM-консоль (Web Serial API)

**Дата:** 2026-11-23  
**Статус:** На согласовании (Design Doc)  
**Автор / Tech Lead:** Senior Product Engineer  

---

## 1. Контекст и Проблема (Intent & The Why)

### Текущая ситуация
Для первичной настройки коммутаторов («из коробки», без IP-адреса) или при аварийном восстановлении (когда инженер отрезал себе SSH неверным правилом firewall, отключением интерфейса или ошибкой в VLAN) сетевой инженер вынужден покидать SwitchBook.

Ему приходится:
1. Подключать физический кабель (USB-to-RJ45 / Type-C Console).
2. Запускать сторонние утилиты (PuTTY, TeraTerm, SecureCRT).
3. Искать в «Диспетчере устройств» Windows назначенный COM-порт (COM3, COM7 и т.д.).
4. Вручную выставлять параметры 9600 8N1.
5. Вручную построчно копировать и вставлять базовые команды инициализации.

### Решение: Zero-Touch WebConsole
Используя современный W3C-стандарт **Web Serial API** (`navigator.serial`), SwitchBook получает возможность напрямую из браузера взаимодействовать с подключенным USB-консольным кабелем. 

Инженер прямо в веб-интерфейсе SwitchBook нажимает **«🔌 Консоль (USB/COM)»**, выбирает обнаруженное USB-устройство в системном диалоге браузера и получает мгновенный доступ к терминалу с готовыми макросами первичной инициализации для **SNR NAG** и **MikroTik RouterOS**.

## 2. Цели, Не-цели и Анти-цели (Goals, Non-Goals, Anti-Goals)

### Цели (Goals):
1. **Прямое подключение к USB-Serial кабелям:** полная поддержка популярных чипов (FTDI, Prolific PL2303, CH340, Silicon Labs CP2102, встроенные Type-C консоли MikroTik/SNR) через нативный `navigator.serial`.
2. **Полноценный VT100/xterm терминал:** переиспользование уже установленных библиотек `@xterm/xterm` (v6.0.0) и `@xterm/addon-fit` для плавной работы, цветного вывода, поддержки горячих клавиш и изменения размера окна.
3. **Настройка параметров последовательного порта:**
   - Скорость (Baud Rate): 9600 (по умолчанию для SNR), 115200 (RouterBOOT, MikroTik), 57600, 38400, 19200.
   - Data bits (8, 7), Stop bits (1, 2), Parity (none, even, odd), Flow control (none, hardware).
4. **Аппаратные спец-сигналы (Send Break):** программная генерация Break-сигнала (250 мс) для сброса паролей и входа в режим RouterBOOT (MikroTik) или загрузчик SNR.
5. **Zero-Touch Provisioning (ZTP) Bar:**
   - Шаблоны быстрой заливки конфигурации под ключевых вендоров (**SNR NAG**, **MikroTik RouterOS**): имя хоста, IP управления, маска, шлюз, учетная запись администратора, включение SSH/Web.
   - Throttling (регулируемая задержка 50–100 мс между отправляемыми строками), чтобы избежать переполнения буфера UART коммутатора при вставке конфига.
   - Интеграция с базой данных SwitchBook: возможность выбрать коммутатор из списка и автоматически подставить его IP, маску и имя в шаблон.
6. **Экспорт и логирование:** кнопки «Скопировать вывод» и «Скачать лог сессии (.txt)».
7. **Информирование о совместимости:** при открытии в неподдерживаемом браузере (Firefox, Safari) отображение дружелюбного баннера с пояснением и предложением открыть в Chromium-браузере.

### Не-цели (Non-Goals):
1. **Серверный COM-порт прокси:** мы не устанавливаем C++ зависимости (`serialport` для Node.js) на бэкенд-сервер. В реальной работе коммутатор подключен кабелем к ноутбуку инженера у стойки, а не к серверу в дата-центре.
2. **Перепрошивка firmware по XMODEM/TFTP через serial:** передача бинарных прошивок по XMODEM не входит в первую версию, фокус — на управлении и первичной конфигурации.

### Анти-цели (Anti-Goals):
1. **Блокировка UI-потока:** никаких синхронных циклов ожидания, которые могут подвесить вкладку браузера при отключении USB-кабеля или зависании свитча.
2. **Захламление сервера:** все операции терминала происходят в браузере клиента, нулевая нагрузка на процессор сервера и сеть.

## 3. Ограничения (Constraints)

* **Поддержка браузеров:** Web Serial API поддерживается всеми браузерами на базе Chromium (Google Chrome, Microsoft Edge, Brave, Opera, Яндекс.Браузер) начиная с версии 89+.
* **Безопасный контекст (Security Context):** Web Serial API доступен только в `https://` или на `localhost` / `127.0.0.1`. При открытии через внешний HTTP (например, `http://IP:3050`) интерфейс выводит понятный баннер с инструкцией (открыть на `localhost`, настроить HTTPS через Nginx или добавить адрес в `chrome://flags/#unsafely-treat-insecure-origin-as-secure`).
* **Жест прав пользователя:** открытие порта инициируется только прямым пользовательским действием (клик по кнопке «Подключить»).

## 4. Архитектурные решения и детальный дизайн (Detailed Decisions)

### 4.1. Модель передачи ZTP (Throttled Streamer)
Вместо сложного и хрупкого конечного автомата (Expect), который может ломаться из-за разных форматов приглашений вендоров (SNR vs MikroTik), используется **Throttled Streamer**:
* Инженер нажимает «Применить шаблон» -> открывается окно предварительного просмотра (Preview) сгенерированного конфига с возможностью отредактировать команды перед отправкой.
* Отправка построчная с настраиваемой задержкой (по умолчанию 60 мс на строку), что полностью исключает переполнение входного FIFO-буфера UART коммутатора.
* Наличие кнопки мгновенной остановки (Pause / Cancel) во время вставки.

### 4.2. Интеграция с инвентарём SwitchBook и IPAM
* **Выбор коммутатора:** В выпадающем списке ZTP Bar можно выбрать существующий свитч из базы: его имя хоста, IP-адрес, маска подсети и шлюз подтягиваются автоматически (маска и шлюз определяются из IPAM/CIDR или берутся из настроек).
* **Настройка с нуля:** Инженер может вручную ввести параметры для любого нового оборудования.
* **Кнопка «Сохранить в базу»:** Если настраивался новый коммутатор, в 1 клик его можно добавить в базу данных SwitchBook (`api.addSwitch`).

### 4.3. Надёжное освобождение COM-порта (Port Lifecycle & Cleanup)
* Использование паттерна с `AbortController`, `reader.cancel()` и `writable.abort()`, гарантирующего, что при закрытии вкладки или модального окна COM-порт не останется заблокированным в Windows (`The port is already open`).

## 5. Рассмотренные подходы (Approaches)

### Подход 1: Автономный клиентский WebSerial с ZTP-макросами (Выбранный)
* Вся работа со стримами `readable` и `writable` происходит на клиенте.
* Терминал подключается напрямую к `TextDecoderStream` и `TextEncoderStream`.
* **Преимущества:** Нулевая задержка, максимальная надежность, нет зависимости от сети/интернета, не требует нативных библиотек на сервере.

### Подход 2: Гибридный серверный COM-мост
* Бэкенд подключается к последовательным портам сервера и стримит их через WebSockets.
* **Почему отклонен:** В 99% случаев сервер SwitchBook изолирован в Docker на виртуальной машине, к которой физически невозможно подключить консольный кабель. Инженер работает со своим ноутбуком.

## 6. Архитектура и Структура Компонентов

```
[Пользовательский интерфейс]
        │
        ├── Header.jsx (Кнопка "🔌 Консоль USB")
        ├── NetworkToolsView.jsx (Инструмент "WebSerial Консоль")
        └── SwitchFaceplate.jsx / SwitchCard.jsx (Кнопка "Консоль")
                    │
                    ▼
       ┌───────────────────────────────┐
       │     WebSerialModal.jsx        │
       │  (Параметры COM, xterm.js,    │
       │   ZTP шаблоны, Send Break)    │
       └──────────────┬────────────────┘
                      │
           [Web Serial API]
                      │
           navigator.serial.requestPort()
                      │
       ┌──────────────┴───────────────┐
       │   port.readable / writable   │
       └──────────────┬───────────────┘
                      │
       [USB-to-Serial / Type-C кабель]
                      │
       [Консольный порт коммутатора]
```

### Ключевые модули:
1. **`src/components/WebSerialModal.jsx`**:
   - Диалог подключения к COM-порту.
   - Панель управления портом (Connect/Disconnect, Baud Rate, Flow Control, Send Break).
   - Интерактивный терминал на базе `@xterm/xterm` и `@xterm/addon-fit`.
   - Панель быстрых шаблонов первичной настройки (SNR NAG, MikroTik RouterOS v6/v7).
   - Вкладка логирования сессии и скачивания дампа консоли.
2. **Точки входа в интерфейсе**:
   - В [src/components/Header.jsx](file:///c:/devs/switchnotes/src/components/Header.jsx) рядом с Web-SSH.
   - В [src/components/NetworkToolsView.jsx](file:///c:/devs/switchnotes/src/components/NetworkToolsView.jsx) в панели сетевых инструментов.
   - В карточке и тулбаре коммутатора для быстрого подключения с предзаполненными параметрами.
